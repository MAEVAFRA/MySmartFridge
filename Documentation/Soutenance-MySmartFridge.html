Contexte & enjeu

Le frigo, c'est vite le désordre.

  • Une gestion des aliments approximative à la maison : produits oubliés, dates de péremption non suivies.
  • Source de gaspillage et de dépenses inutiles au quotidien.
  • Les solutions existantes sont trop complexes, mono-utilisateur, ou inadaptées au foyer partagé.
≈ 30 kg
d'aliments jetés par personne et par an en France (estimation ADEME)

👉 D'où MySmartFridge : une solution complète, moderne et collaborative pour inventorier, anticiper et partager.

Périmètre du projet

Deux applications à livrer

Le brief impose une application web et une application mobile, adossées à une même API REST.

Application web · React

Responsive / PWA — le back-office complet : inventaire, péremptions, scan OCR de tickets, recettes, dépenses & split, courses, statistiques, foyer multi-membres.

Application mobile · Flutter

Client natif de l'API pensé pour la mobilité : scan de code-barres, inventaire, alertes de péremption, courses cochables en magasin (hors-ligne).

Socle commun : API REST, PostgreSQL, auth JWT, multi-foyers.  ·  Hors périmètre : IA de reconnaissance d'image & intégration livraison.

Un choix technique argumenté

OCR : pourquoi Tesseract.js ?

SolutionCoûtOfflinePrécision FR
Tesseract.js ✔GratuitOui70–80 %
Google VisionTier limitéNon95 %+
OpenAI GPT-4oPayantNon95 %+
AWS TextractPayantNon90 %+
Mistral PixtralTier limitéNon85 %+
  • Coût nul — pas de carte bancaire, pas de quota.
  • 100 % local — cohérent avec Docker, les tickets ne quittent jamais la machine (confidentialité).
  • Intégration triviale (npm) + support français natif.
La précision est compensée par un écran de confirmation ; la logique est isolée pour permettre une migration cloud ultérieure.

Bilan

Réalisations & difficultés

Livré
  • Web React complet : tous les Must + majorité des Should/Could.
  • API robuste : JWT, MVC, 30 tables, migrations, OCR, proxy OFF.
  • App mobile Flutter : scanner code-barres, courses hors-ligne, thème sombre.
  • Documentation fournie : CDC, US, MCD, doc API, conformité.
Difficultés
  • OCR : arbitrage coût / précision / confidentialité → Tesseract.js.
  • Flutter : montée en compétence de toute l'équipe sur le mobile.
  • Temps réel courses : pas de WebSocket → pull + file offline.
  • Multi-foyer mobile : géré en mono-foyer côté app.
Regard critique

Ce qui reste à faire

À finaliser (web & mobile)
  • Notifications de péremption (push / e-mail) — local mobile puis FCM + job CRON serveur.
  • Synchro temps réel de la liste de courses (WebSocket / SSE).
  • Date d'ouverture d'un produit (durée réduite) — donnée en base non exploitée.
  • Filtre catégorie & tri par quantité dans l'inventaire.
À porter sur le mobile
  • Recettes : suggestions anti-gaspi, détail, favoris, « j'ai cuisiné ».
  • Dépenses & budgets : split, tableau des soldes, remboursements.
  • Foyer multi-membres (mobile mono-foyer) & statistiques.
  • OCR ticket & reset password (deep link) — le backend existe déjà.
Bonne nouvelle : l'API et la base couvrent déjà ces besoins — le reste-à-faire est surtout côté interface mobile.
